Final Docs refactor

Onboarding cut from 2-4 weeks to days: a YAML change, not a code release.

Final Docs governs how PRMI assembles and delivers post-closing packages to its investor banks, where delays put funding lines and regulatory standing at risk. Onboarding each new investor took 2-4 weeks of bespoke coding and QA, so growing the investor network was capped by engineering capacity, not by business appetite.

  • Approach: treat an investor as data, not code. I rebuilt the monolith into config-driven dynamic dispatch: investor-specific logic lives in per-investor YAML definitions mapped to specialized handler functions, so onboarding became a configuration change instead of code surgery.
  • Result: 4 new investors integrated in a single month, work that previously consumed a full quarter of engineering capacity. Investor expansion now moves at deal speed rather than dev speed, and the architecture was adopted as the template for two other automation initiatives.
Role
Architecture and build, end to end
Stack
Python, YAML config, Strategy pattern, Pandas
